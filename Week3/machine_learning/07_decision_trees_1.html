The Core Idea

A Flowchart of Yes/No Questions

Think of the game "20 Questions." Is it an animal? Does it have fur? Is it bigger than a cat? Each answer narrows down the possibilities until you land on one. A decision tree does exactly this with data -- except it figures out the best questions to ask, and in what order, entirely from the training data itself.

To predict on a new row: start at the top, answer each question using that row's feature values, follow the yes/no branch, repeat until you reach an answer at the bottom. That's the whole prediction process -- no distances, no coefficients, just a sequence of comparisons like tenure_months < 12?

The Central Question

How Does a Tree Decide What to Ask?

At every node, the tree considers every feature and every possible threshold ("tenure < 6?", "tenure < 12?", "monthly_charges < 80?" ...) and picks whichever single split makes the two resulting groups as "pure" as possible -- meaning each group is dominated by one class as much as possible.

"Pure" in plain terms: a group of 40 customers where all 40 churned is perfectly pure. A group of 40 where 20 churned and 20 stayed is maximally impure -- a coin flip, telling you nothing. The tree's whole strategy is repeatedly asking whichever question splits the data into groups that are as far from "coin flip" as possible.

In [ 7 ]:
Measuring "Purity," Option 1

Gini Impurity

Gini = 1 − Σ (fraction of each class)²

A number from 0 (perfectly pure -- every row the same class) to 0.5 (perfectly mixed, for two classes). No calculus required to use it -- just: square each class's share of the group, add them up, subtract from 1.

Pure group: 40 churned, 0 stayed

Gini = 1 − (1.0² + 0.0²) = 1 − 1 = 0 -- perfectly pure, the best possible score.

Mixed group: 20 churned, 20 stayed

Gini = 1 − (0.5² + 0.5²) = 1 − 0.5 = 0.5 -- maximally impure, the worst possible score for two classes.

A split's overall Gini is the weighted average of the Gini of its two resulting groups. The tree tries many candidate splits and keeps whichever one produces the lowest weighted Gini -- i.e. the purest resulting groups.

The split-level formula, spelled out: Gini_split = (n_left / n) × Gini_left + (n_right / n) × Gini_right -- each child's impurity, weighted by what fraction of the rows landed in it. The next slide runs this formula on an actual dataset, start to finish.

In [ 8 ]:
Seeing the Arithmetic Once, in Full

Worked Example: Which Question Should the Root Ask?

Ten training rows, two candidate questions. This is the exact computation DecisionTreeClassifier runs internally, just done by hand once so the formula stops being abstract.

Candidate A: tenure < 12?

Yes (5 rows: #1,2,3,4,9) → 4 churn, 1 stay
Gini = 1 − (0.8² + 0.2²) = 0.32

No (5 rows: #5,6,7,8,10) → 0 churn, 5 stay
Gini = 1 − (0² + 1²) = 0.0

Weighted Gini = 0.5×0.32 + 0.5×0.0 = 0.16

Candidate B: contract = month?

Month (5 rows: #1–5) → 3 churn, 2 stay
Gini = 1 − (0.6² + 0.4²) = 0.48

Year (5 rows: #6–10) → 1 churn, 4 stay
Gini = 1 − (0.2² + 0.8²) = 0.32

Weighted Gini = 0.5×0.48 + 0.5×0.32 = 0.40

Candidate A wins -- 0.16 is lower than 0.40, so tenure < 12? becomes the root question, exactly as it did in the vocabulary diagram a few slides back. In information-gain terms: A drops impurity by 0.48 − 0.16 = 0.32, while B only drops it by 0.48 − 0.40 = 0.08. The tree checks every feature and every threshold this way and simply keeps the single biggest drop.

In [ 9 ]:
Measuring "Purity," Option 2

Entropy and Information Gain

Entropy, borrowed from information theory, measures the same basic idea as Gini -- how mixed a group is -- on a slightly different numeric scale (0 = pure, up to 1 for a 50/50 mix of two classes, using logarithms instead of squares).

Information Gain is simply "how much did entropy drop after this split?" -- the bigger the drop, the more that question told you. A tree using entropy picks whichever split maximizes information gain -- the mirror image of picking minimum Gini.

In practice, Gini and entropy almost always pick the same splits -- Gini is the scikit-learn default ( criterion='gini') mainly because it's a little cheaper to compute (no logarithms). Don't spend much energy agonizing over which one to choose.

Entropy = −Σ pi log₂(pi)

Same recipe as Gini: figure out each class's fraction p_i in the group, but instead of squaring, multiply by its own log₂ and sum, then flip the sign. On the same root group as the Gini example (4 churn, 6 stay -- p = 0.4, 0.6):

Entropy = −(0.4 × log₂0.4 + 0.6 × log₂0.6) = −(0.4×(−1.32) + 0.6×(−0.74)) ≈ 0.971

Information Gain = Entropy(parent) − Σ (nchild/n) × Entropy(child)

Structurally identical to the weighted-Gini formula from two slides ago -- parent's score minus the size-weighted average of the children's scores. A tree using criterion='entropy' just swaps this formula in for Gini at every split; the recursive splitting process around it doesn't change at all.

In [ 10 ]:
Building the Whole Tree

The Recursive Splitting Process

The tree doesn't just do this once -- it repeats the "find the best split" step on each resulting group, over and over, building the tree top-down.

  • 1. Start with all training rows in one big group (the root).
  • 2. Find the single best question to split this group into two purer sub-groups.
  • 3. Repeat step 2 on each sub-group, independently, treating each as its own smaller problem.
  • 4. Keep going until a stopping rule is hit -- a group is already pure, or a limit like max depth is reached.
  • 5. Whatever's left at the bottom becomes a leaf: the majority class (classification) or the average value (regression) of the rows that ended up there.

This "keep splitting until told to stop" strategy is called CART (Classification and Regression Trees) -- the algorithm scikit-learn's DecisionTreeClassifier/Regressor both implement.

A Genuine Advantage

You Can Actually Look at a Decision Tree

Unlike almost every other model in this course, a small decision tree can be drawn out and read directly, question by question -- no coefficients to interpret, no black box.

sklearn.tree.plot_tree(model) draws the exact flowchart the model learned -- every question, every Gini score, every leaf's prediction and confidence, visible at a glance. The notebook uses this constantly, because seeing the actual tree is the fastest way to build real intuition for what's happening.

The Central Weakness

Why Trees Overfit So Easily

Left alone, a tree will keep splitting until every single leaf is perfectly pure -- which, taken to the extreme, means one leaf per training row. That's not a model that learned a pattern; it's a lookup table that memorized the training data.

This is Lecture 01's overfitting picture in its purest form. A fully grown tree gets 100% accuracy on training data almost by construction -- and often noticeably worse accuracy on new data, because it learned the training set's specific noise, not the general pattern underneath it.

The fix has a name: pruning -- deliberately keeping the tree simpler than it "wants" to be, on purpose.

In [ 13 ]:
Putting a Number On It

The Classic Depth-vs-Accuracy Curve

Train the same tree at every max_depth from 1 to 10 and plot accuracy on the training set against accuracy on a held-out test set. This shape shows up so often it's worth memorizing.

The widening gap between the two lines is overfitting, made visible. Past the sweet spot, every extra layer of depth buys the tree a little more training accuracy and costs it real generalization -- which is precisely the gap pruning is designed to close.

In [ 14 ]:
Stopping Early

Pre-Pruning: Limits Set Before Training

The simplest fix -- tell the tree it isn't allowed to grow past certain limits, decided in advance.

HyperparameterWhat it limits
max_depthHow many questions deep the tree is allowed to go
min_samples_splitA group must have at least this many rows before it's allowed to split further
min_samples_leafEvery leaf must end up with at least this many rows

These are hyperparameters, tuned exactly like any other (Lecture 04) -- too restrictive and the tree underfits; too loose and it overfits. Cross-validation, not guessing, is how you'd actually choose good values.

In [ 15 ]:
Growing First, Trimming After

Post-Pruning: Cost-Complexity Pruning

Instead of stopping early, grow the tree all the way out -- then go back and snip off branches that aren't earning their keep, balancing accuracy against simplicity.

ccp_alpha controls this trade-off directly: a higher value prunes more aggressively, removing branches unless they improve training accuracy by more than alpha. At alpha = 0, nothing gets pruned -- the full, likely-overfit tree.

Same idea as Ridge/Lasso's `alpha` from Lecture 02: a single knob trading model complexity for simplicity, tuned via cross-validation rather than picked by eye.

In [ 16 ]:
Seeing the Difference Directly

Pruned vs. Unpruned, Side by Side

The single most convincing way to teach overfitting on a tree: grow one with no limits at all, grow another with sensible limits, and look at both the tree diagrams and the train-vs-test accuracy gap.

What to expect: the unpruned tree will show huge, sprawling branches and near-perfect training accuracy -- with a noticeably worse test accuracy. The pruned tree will look smaller and "less impressive" on paper, but its train and test accuracy will sit much closer together -- the real signal of a trustworthy model. The notebook shows this exact comparison with real numbers.

In [ 17 ]:
A Deeper Look Than Feature Selection Had Room For

Feature Importance, Revisited

Lecture 03 used .feature_importances_ without fully explaining where the numbers come from. Now you have the vocabulary: a feature's importance is based on how much it reduced impurity, summed across every split in the tree that used it, weighted by how many rows passed through that split.

The caveat from Lecture 03, explained properly now: if two features are highly correlated, whichever one the tree happens to split on first gets most of the importance credit -- the other looks unimportant purely because the first one already did most of that job. Low importance doesn't always mean "irrelevant."

In [ 18 ]:
A Structural Limitation

Trees Can Only Draw Straight, Axis-Aligned Lines

Every split is a single feature compared to a single threshold -- "tenure < 12," never "tenure + 0.5 × monthly_charges < 40." Stack enough of these rectangular splits together and a tree can approximate almost any boundary shape -- but it can never draw a clean diagonal line in one step.

The visual tell: a tree's decision boundary always looks like a collection of rectangles (stacked horizontal and vertical cuts), never a smooth diagonal or curve. If the true boundary between classes genuinely is diagonal, a tree needs many small steps to approximate it -- whereas a method built around lines and margins (SVM, Lecture 10) draws exactly that boundary in one shot.

The Limitation, Drawn Out

Staircase Boundaries vs. a Clean Diagonal

Two classes that are genuinely separated by a diagonal line. Watch what each model type actually draws between them.

A Decision Tree's Boundary

The amber line is what stacking axis-aligned splits produces -- a staircase hugging the true diagonal (violet, dashed), needing several splits to get close.

What a Linear Model Draws (SVM / Logistic Regression)

One split, in one direction, and the two classes are perfectly separated -- because the model's boundary shape isn't restricted to horizontal/vertical cuts.

Neither shape is universally "better." A staircase is the wrong tool for a diagonal boundary, but it's exactly the right tool for boundaries that genuinely bend at right angles (e.g. rule-like data: "if tenure < 12 and monthly_charges > 80"). Knowing which shape your data actually needs is part of model selection.

The Honest Trade-offs

Pros and Cons of Decision Trees

Strengths

  • No scaling needed -- splits compare one feature to a threshold, unaffected by units (Lecture 05's scaling recap, revisited)
  • Handles non-linear relationships and interactions natively, with no manual feature engineering
  • Genuinely interpretable -- you can read the actual logic, not just trust a score
  • Works on both regression and classification with the same core idea

Weaknesses

  • Overfits very easily without pruning
  • High variance / instability -- a small change in the training data can produce a noticeably different tree (next slide)
  • Axis-aligned splits only -- clumsy at diagonal boundaries
  • A single tree's accuracy often trails other methods once properly tuned
In [ 21 ]:
The Cliffhanger for Session 2

The Instability Problem

Train a tree on 100 customers, then train another tree after removing just a handful of rows -- the two trees can end up asking completely different first questions, and look structurally very different, even though almost all the same data went into both.

Why this happens: the very first split affects every split beneath it -- a slightly different "best" first question sends different rows down different paths from that point on, cascading into a different-looking tree throughout. Small input changes, big structural changes -- the textbook definition of a high-variance model.

The idea that fixes this is deceptively simple: if one tree is unstable and unreliable, what if you trained many slightly-different trees and let them vote? That's a Random Forest -- and it's the entire subject of next session.

In [ 22 ]:
The Regression Version, Briefly

Regression Trees: Splitting on Variance Reduction

Gini and entropy only make sense for categories. For a numeric target (like predicting price), a regression tree instead picks whichever split most reduces the variance of the target within each resulting group -- the numeric equivalent of "purity."

The intuition carries over directly: a "pure" leaf for regression is one where every row's target value is close to the same number -- low variance, a confident, narrow prediction. A "mixed" leaf has wildly different target values lumped together -- high variance, an unreliable average.
