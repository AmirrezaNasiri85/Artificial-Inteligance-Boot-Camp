What Is Machine Learning?

A Program That Improves With Experience

The oldest working definition still holds up: a computer program is said to learn if its performance at some task improves with experience — without a human rewriting its rules each time.

Tom Mitchell's formal definition (1997): a program learns from experience E with respect to task T and performance measure P, if its performance on T, measured by P, improves with E.

T — Task

Classify an email as spam or not spam

P — Performance

Percentage of emails classified correctly

E — Experience

A dataset of past emails, each labeled spam / not spam

Notice what's not in that definition: nobody wrote an explicit rule like if subject contains "free money": spam. The rules get discovered from E — that single shift is the whole idea of machine learning.

The Core Shift

Traditional Programming vs. Machine Learning

Same three ingredients — rules, data, answers — but machine learning swaps which one is the output and which ones are the input.

That output — the learned rules — is what we call a model. Every algorithm in this course (LinearRegression, LogisticRegression, DecisionTreeClassifier, SVC) is a different strategy for discovering rules from data — the strategies differ, but every one of them is doing this same swap.

Why Machine Learning, Why Now

Three Forces Converged

The core mathematical ideas behind most of this course — linear regression, decision trees, even neural networks — are decades old. What changed recently is the environment around them.

Data

Every click, transaction, and sensor reading is now logged by default — the raw "experience" (E) a model needs, at a scale that didn't exist 20 years ago.

Compute

GPUs and cloud computing turned training that once took weeks into a process that takes minutes — including everything you'll run on your own laptop in this course.

Algorithms

Better training techniques and libraries like scikit-learn turned research-lab code into a few lines anyone can call: .fit(), .predict().

None of the three alone would have been enough — a brilliant algorithm with no data has nothing to learn from, and mountains of data with no compute are just an expensive archive.

The Three Paradigms

Supervised, Unsupervised, Reinforcement

Every ML problem falls into one of three families, split by what kind of experience (E) the model gets to learn from.

Supervised

Learn from data that's already labeled with the right answer. The focus of this entire course. Example: predicting house prices from past sales.

Unsupervised

Find structure in unlabeled data — no "right answer" is given. Example: grouping customers into segments from behavior alone.

Reinforcement

Learn by trial and error, guided by reward signals. Example: a game-playing agent, or a robot learning to walk.

Every algorithm named in this course — Linear Regression, Logistic Regression, Decision Trees, SVM — is supervised. That's where we're spending our time, starting today.

Inside Supervised Learning

Two Kinds of Question: Regression vs. Classification

Supervised learning splits again, this time by what kind of answer you're predicting — a number, or a category.

Regression — predicting a number

Output is continuous: a price, a temperature, a salary. First up next lecture: Linear Regression.

Classification — predicting a category

Output is a label: spam/not-spam, churn/stay, malignant/benign. Later lectures: Classification, Decision Trees, Logistic Regression, SVM.

For Context, Not the Focus

Where Unsupervised & Reinforcement Learning Fit

You won't build these in this course, but the vocabulary comes up constantly in the field — worth recognizing by name.

Clustering

Grouping similar rows without being told the groups in advance. If our churn capstone hadn't had a churn label, we could still have clustered customers by behavior and described the segments afterward.

Dimensionality Reduction

Compressing many correlated features into a handful of components — used to visualize high-dimensional data in 2D, or to speed up training on very wide tables.

Reinforcement Learning

An agent takes actions in an environment and learns from reward, not from labeled examples — how game-playing systems and robotics are typically trained. Structurally the most different of the three paradigms from what you'll build this course.

Vocabulary You'll Use Every Lecture

The Anatomy of a Model

Same four words, in every algorithm from here on — worth anchoring to the churn capstone you already built.

Features — X

The input columns a model is allowed to look at. In the capstone: tenure_months, contract, monthly_charges …

Label / Target — y

The answer the model is trying to predict. In the capstone: churn (0 or 1).

Parameters

Numbers the model learns from data during .fit() — e.g. the slope and intercept of a line, or split thresholds in a tree.

Hyperparameters

Settings you choose before training, not learned from data — e.g. max_depth, n_estimators, what GridSearchCV searched over in the capstone.

A trained model is really just: a function that maps X → y, plus the parameter values that made it fit the training data as well as it could.

The Rule You Cannot Break

Never Grade Your Own Homework

A model evaluated on the same data it trained on will always look better than it really is — it's had a chance to memorize the answers, not learn the pattern behind them.

This is exactly what train_test_split(X, y, test_size=0.2, stratify=y) did in the capstone. stratify=y matters whenever the target is imbalanced (like a ~20-35% churn rate) — it keeps the same churn rate in both pieces, so the test set isn't accidentally easier or harder than training.

A single split still depends on which rows happened to land in the test set — that uncertainty is exactly what Cross-Validation (Lecture 04) is built to fix.

In [ 12 ]:
The Central Failure Mode

Underfitting, Good Fit, Overfitting

The same data, fit three different ways — only the middle one will generalize to new customers it hasn't seen.

Underfit

High bias. The model is too simple to capture the real pattern — it misses the trend even in the data it trained on.

Good Fit

Balanced. Follows the real trend without chasing every point — this is what "just right" looks like.

Overfit

High variance. Threads every training point exactly, including the noise — will perform worse on data it hasn't seen.

In [ 13 ]:
Naming the Tradeoff

The Bias-Variance Tradeoff

The dartboard analogy: bias is how far off-target your average throw is; variance is how scattered your throws are from each other.

Low Bias · Low Variance

The goal. Tight cluster, centered on the bullseye.

Low Bias · High Variance

Overfitting. Centered on average, but wildly inconsistent — this is what an overfit model looks like across different samples.

High Bias · Low Variance

Underfitting. Consistent, but consistently wrong — tightly clustered, off-target.

High Bias · High Variance

The worst of both — wrong on average, and inconsistent besides.

The Uncomfortable Truth

Data Quality Beats Algorithm Choice

"Garbage in,
garbage out."

Swapping Logistic Regression for a fancier model on messy, poorly-engineered data usually buys you almost nothing. Cleaning missing values, fixing a skewed distribution, and engineering one genuinely informative feature usually buys you far more than switching algorithms — exactly what the capstone's cleaning and feature-engineering steps (5.2) did before any model was trained.

  • Missing data handled badly quietly biases every model trained on it.
  • Leaky features (accidentally including information from the future) make a model look great in testing and fail immediately in the real world.
  • Feature Engineering (Lecture 05) is often the single highest-leverage thing you can do — more than any hyperparameter in GridSearchCV.

A Preview, Not a Deep Dive

How Do We Know If a Model Is Good?

Each family of problems gets its own vocabulary for "good" — full treatment comes with Classification and Cross-Validation, but you'll see these words constantly starting next lecture.

For Regression

MSE — average squared distance between predicted and actual values. R² — the share of variance in the target the model explains, from 0 to 1.

For Classification

Accuracy — percent correct. Precision & Recall — how costly false positives vs. false negatives are, exactly like the churn capstone's confusion matrix.

The one number to distrust on its own: accuracy, on an imbalanced target. A model that always predicts "no churn" on a dataset that's 80% "no churn" is 80% accurate — and useless.
