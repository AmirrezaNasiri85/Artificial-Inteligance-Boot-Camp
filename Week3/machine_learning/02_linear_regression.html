The Question It Answers

"Given X, What Number Is y?"

Linear regression assumes the simplest possible relationship that could connect a feature to a number: a straight line. Bigger house → higher price. More experience → higher salary. It's asking whether that simple assumption is good enough — and very often, it is.

Good candidate questions

  • Predict a house price from square footage
  • Predict salary from years of experience
  • Predict exam score from hours studied

Poor candidate questions

  • Predict a category (churn yes/no) — that's classification, Lecture 06+
  • Predict something with a sharp threshold effect, not a smooth trend
  • Predict something where the true relationship curves sharply (Part 8 covers this)

Simple Linear Regression

One Feature, One Equation

ŷ = w·x + b

ŷ (y-hat)

The model's predicted value — distinguished from the real, observed y in the training data.

w — weight / slope

How much ŷ changes for each +1 unit of x. This is a parameter — learned, not chosen.

b — bias / intercept

The predicted value when x = 0. Also a learned parameter.

"Training the model" means exactly one thing here: searching for the single best pair of numbers (w, b) — nothing more mysterious than that.

In [ 5 ]:
What "Best" Means, Geometrically

Minimizing the Vertical Gaps

Of all the lines you could draw through a scatter plot, the "best" one is defined as the one that makes the vertical distances between each point and the line — the residuals — as small as possible, overall.

A residual can be positive (point above the line) or negative (below it) — which is exactly why the next slide squares them before adding them up.

In [ 6 ]:
Turning "Best" Into a Number

The Cost Function: Mean Squared Error

MSE = (1/n) Σ (yᵢ − ŷᵢ)²

For every training point, take the residual, square it (so positive and negative errors don't cancel out, and big misses are punished disproportionately more than small ones), then average over all n points.

"Training" = finding the (w, b) that makes this single number as small as possible. Every value of (w, b) defines a different line, and therefore a different MSE — training is a search over that space.

This is also why linear regression is called Ordinary Least Squares (OLS) — "least squares" is just another name for "minimum MSE."

In [ 7 ]:
How the Best Line Actually Gets Found

Two Roads to the Same Answer

The Normal Equation

A direct, closed-form formula — solve for (w, b) in one calculation using linear algebra (the same np.linalg.lstsq you saw in the capstone's advanced NumPy section). Exact, but gets slow as the number of features grows very large.

Gradient Descent

An iterative search — start with a random guess, and repeatedly nudge (w, b) in the direction that reduces MSE, a small step at a time. Scales far better to huge datasets and huge feature counts.

sklearn.linear_model.LinearRegression uses the normal-equation route internally — for the dataset sizes in this course, both methods land on the identical line. You'll implement both by hand in the notebook to see why.

In [ 8 ]:
A Closer Look

Gradient Descent: Walking Downhill

Picture the cost function as a valley — the height at any point is the MSE for that (w, b). Gradient descent is standing somewhere on that valley wall and always stepping in the steepest downhill direction.

Learning rate

The size of each step. Too small: painfully slow to converge. Too large: overshoots the valley floor and can even diverge.

Convergence

Stop stepping once the cost stops meaningfully decreasing — the notebook plots this curve directly so you can watch it happen.

In [ 9 ]:
From One Feature to Many

Multiple Linear Regression

ŷ = w₁x₁ + w₂x₂ + … + wₙxₙ + b

Nothing conceptually new — just one weight per feature instead of one. A house's price might depend on x₁ = area, x₂ = bedrooms, x₃ = age, all at once. The cost function (MSE) and the fitting process are identical to the single-feature case.

In vector form this is just ŷ = w · x + b — a dot product between a weight vector and a feature vector. This is precisely what LinearRegression().fit(X, y) solves when X has more than one column.

In [ 10 ]:
What the Numbers Actually Mean

Reading a Fitted Coefficient

Each wᵢ answers one specific question: "holding every other feature constant, how much does ŷ change for +1 unit of this feature?" The phrase "holding constant" is doing real work — it's what separates a coefficient from a simple correlation.

Units matter

A coefficient of 150 on area_sqft means "+$150 in price per +1 sqft" — not a general measure of importance you can compare across differently-scaled features without standardizing first.

Comparing magnitudes fairly

To compare which feature matters "most," standardize every feature first (StandardScaler) — then coefficients are all in the same units (standard deviations) and become directly comparable.

In [ 11 ]:
A Quick Recap

Linear Regression Only Understands Numbers

A column like neighborhood (Downtown / Suburb / Rural) can't be multiplied by a weight directly — it has to become numeric first, exactly the way the capstone's ColumnTransformer + OneHotEncoder handled contract and payment_method.

One-hot encoding turns one categorical column into several 0/1 columns — each gets its own coefficient, read as "the price difference vs. the baseline category, all else held constant."

Judging the Fit

MSE, RMSE, MAE, and R² — When to Use Which

MetricWhat it tells youWatch out for
MSEAverage squared errorNot in the same units as y (units²)
RMSE√MSE — back in y's original unitsStill punishes big misses heavily
MAEAverage absolute error, in y's unitsTreats all errors proportionally — more robust to outliers
R²Share of variance in y explained, 0–1Always increases when you add any feature, even useless ones

R² close to 1 isn't automatically "good" — a model can have high R² on training data purely from overfitting. This is exactly why Lecture 01's train/test split rule still applies here: always report these metrics on the test set.

In [ 13 ]:
The Fine Print

The Assumptions Behind the Guarantees

Linear regression's coefficients and p-values are only trustworthy if a handful of conditions roughly hold. Remembered by the acronym L.I.N.E.

Linearity

The true relationship between X and y is actually a straight line — checked visually with a residual plot (next slide).

Independence

Residuals don't depend on each other — a common violation in time series, where today's error correlates with yesterday's.

Normality

Residuals are roughly normally distributed — matters most for the validity of confidence intervals and p-values, less for raw prediction accuracy.

Equal variance

"Homoscedasticity" — residual spread stays roughly constant across the full range of predictions, rather than fanning out.

In [ 14 ]:
Checking L.I.N.E. in Practice

Reading a Residual Plot

Plot residuals (y-axis) against predicted values (x-axis). The pattern — or lack of one — tells you which assumption, if any, is in trouble.

Healthy

Random scatter around zero, no pattern, roughly constant spread — L.I.N.E. holds.

Trouble: Fanning & Curvature

Spread grows with predicted value (fanning = unequal variance) and/or curves (a hint linearity itself is violated).

In [ 15 ]:
A Different Kind of Problem

Multicollinearity: When Features Overlap

area_sqft and bedrooms tend to move together — bigger houses usually have more bedrooms. When two features carry almost the same information, the model struggles to tell which one deserves the credit, and coefficients can become unstable (even flipping sign) without prediction accuracy suffering at all.

VIF (Variance Inflation Factor) quantifies this: regress each feature on all the others, and see how well they predict it. VIF > 5–10 on a feature is the conventional warning sign of serious overlap. The notebook computes this directly with plain LinearRegression — no extra library needed.

This is exactly the problem Feature Selection (next lecture) gives you formal tools to address — dropping or combining redundant features before they destabilize a model.

In [ 16 ]:
When a Straight Line Isn't Enough

Polynomial Regression

If a residual plot shows real curvature, the fix isn't a new algorithm — it's adding curved features (x², x³, …) and fitting the exact same linear regression on top of them. The model is still linear in its weights — only the input features got richer.

ŷ = w₁x + w₂x² + b is still "linear regression" in the technical sense — it's linear in w₁ and w₂, even though the curve it draws is not a straight line.

The catch: degree 2 might capture a real curve; degree 15 will weave through every training point and fail badly on new data — this is Lecture 01's overfitting picture, showing up again with a dial you can literally turn (PolynomialFeatures(degree=...)), which the notebook demonstrates directly.

In [ 17 ]:
A Preview, Not the Full Story

Ridge & Lasso: Penalizing Complexity

Both add a penalty term to the MSE cost function that discourages large coefficients — directly fighting the overfitting picture from the last two slides, without you having to manually pick a polynomial degree.

Ridge (L2 penalty)

Shrinks every coefficient toward zero, smoothly — good when most features carry some real signal and multicollinearity is the concern.

Lasso (L1 penalty)

Can shrink coefficients all the way to exactly zero — effectively performing feature selection as a side effect of fitting the model.

This is deliberately a first look — Feature Selection (next lecture) returns to Lasso specifically as one of several formal tools for deciding which features earn a place in the model.
