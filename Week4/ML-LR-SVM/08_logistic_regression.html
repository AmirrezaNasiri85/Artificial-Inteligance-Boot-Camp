Recap

Last Time, and Where This Sits

Lectures 07-08 gave trees and ensembles as one family of classifiers -- flexible, rectangular decision boundaries, built by splitting. Today's algorithm is a completely different shape of idea: a single smooth equation, closely related to the very first algorithm in this course.

Worth saying out loud: "Logistic Regression" and "Linear Regression" share an equation almost entirely -- w·x + b -- the entire rest of today's lecture is about what happens to that number afterward.

In [ 3 ]:
The Motivating Problem

Why Not Just Use Linear Regression?

A tempting first idea: fit a straight line to 0/1 data, treat the line's output as a probability. Two things go wrong immediately, and both are visible directly in the plot below.

The fix: keep the same linear combination w·x + b underneath, but pass it through a curve that squashes any output into a valid probability between 0 and 1, no matter how large or small the input. That curve is the sigmoid function, next.

In [ 4 ]:
The Curve That Makes It Work

The Sigmoid Function

sigmoid(z) = 1 / (1 + e−z)

No calculus needed to use this well: large positive z squashes toward 1, large negative z squashes toward 0, and z = 0 always lands exactly on 0.5 -- the genuine "coin flip" point.

In [ 5 ]:
Putting the Two Pieces Together

The Logistic Regression Equation

P(y=1) = sigmoid(w·x + b)

Step 1 -- the linear part

z = w·x + b -- exactly Linear Regression's equation. Weighted sum of features plus a bias, computed identically to Lecture 02.

Step 2 -- the squashing part

sigmoid(z) takes that number and turns it into a genuine probability. Above 0.5 → predict class 1; below 0.5 → predict class 0 (Lecture 06's threshold, unchanged).

"Training" the model means exactly what it meant in Lecture 02 -- finding the best (w, b) -- just judged by a different cost function, since MSE doesn't make sense for probabilities (Part 10).

In [ 6 ]:
A Different Way to Talk About Chance

Odds: Not the Same as Probability

odds = p / (1 − p)

If a customer has a 75% probability of churning, the odds of churning are 0.75 / 0.25 = 3 -- "3 to 1," or three times more likely to churn than not. Same underlying fact, a different, very common way of expressing it (bookmakers, medical studies, and Logistic Regression itself all prefer odds over raw probability for good mathematical reasons).

Probability lives between 0 and 1. Odds live between 0 and infinity -- and that difference in range turns out to matter a lot for the next slide.

In [ 7 ]:
Why It's Called "Logistic"

Log-Odds: the Straight Line Hiding Inside the Curve

Take the logarithm of the odds, and something clean happens: the S-shaped probability curve becomes a perfectly straight line again.

This is the whole reason for the name "logistic regression": it's literally a linear regression -- on the log-odds. The model fits a straight line in log-odds space; converting that line back to a probability is what produces the S-curve you actually see and use.

In [ 8 ]:
Reading a Fitted Coefficient

Interpreting Coefficients via Odds Ratios

Because the model is linear in log-odds, a coefficient w means: "+1 unit of this feature adds w to the log-odds." That's awkward to reason about directly -- exponentiating it gives something much more intuitive.

ew is the odds ratio -- how much the odds get multiplied by, per +1 unit of the feature. A coefficient of w = 0.7 gives e0.7 ≈ 2.0 -- "+1 unit of this feature roughly doubles the odds of the outcome."

Odds ratio above 1 means the feature increases the odds; below 1 means it decreases them; exactly 1 means no effect at all. This is exactly what np.exp(model.coef_) computes.

In [ 9 ]:
A Direct Consequence of the Equation

The Decision Boundary Is Always a Straight Line

The boundary between "predict class 0" and "predict class 1" is exactly where sigmoid(z) = 0.5 -- which happens exactly where z = w·x + b = 0. That's the equation of a straight line (in 2D) or a flat plane (in higher dimensions) -- never a curve, never a rectangle.

Compare the three families you now know: KNN draws a boundary that can wiggle arbitrarily; a Decision Tree draws one built from rectangular staircases; Logistic Regression can only ever draw one straight line. Part 16 shows all three side by side, on the same data.

In [ 10 ]:
How the Best Line Gets Found

Maximum Likelihood, Intuitively

Linear Regression finds (w, b) by minimizing squared error. Logistic Regression instead searches for the (w, b) that makes the training data's actual labels look as probable as possible under the model.

In plain terms: for every customer who really churned, the model wants to have assigned a high probability to churn. For every customer who really stayed, it wants to have assigned a low probability to churn. "Maximum likelihood" just means: search for the (w, b) that gets as many of these probability assignments as confidently-correct as possible, across the whole training set at once.

No need to carry the underlying calculus forward -- the practical result is the cost function on the next slide, which is what actually gets minimized during training.

In [ 11 ]:
The Cost Function

Log Loss (Binary Cross-Entropy)

Read the curves' shape, not just their formula: a confident, correct prediction (right side of the teal curve, left side of the coral curve) costs almost nothing. A confident, wrong prediction shoots toward infinity -- the model is punished far more severely for being confidently wrong than for being cautiously wrong. This asymmetric punishment is exactly what "training" minimizes, across every row in the training set, averaged.

In [ 12 ]:
Finding the Minimum

Gradient Descent, Once More

Unlike Linear Regression, log loss has no clean closed-form solution -- there's no normal-equation shortcut. Logistic Regression is trained with gradient descent (or a close relative of it) every time: start with a guess for (w, b), repeatedly step in the direction that reduces log loss, stop once it stops improving meaningfully.

Exactly Lecture 02's gradient descent, pointed at a different cost function. Feature scaling still matters for the same reason it did there -- unscaled features distort the cost surface and slow convergence.

In [ 13 ]:
Controlling Complexity, Revisited

L1 and L2 Regularization, Now on Logistic Regression

Ridge (L2) and Lasso (L1) from Lecture 02 apply here in exactly the same spirit -- adding a penalty for large coefficients to the cost function being minimized.

Read left to right: with no penalty, coefficients can grow large and noisy. L2 shrinks every coefficient toward zero, smoothly. L1 shrinks some coefficients all the way to exactly zero -- performing feature selection as a side effect of fitting, precisely like Lecture 02's Lasso and Lecture 03's embedded methods.

In [ 14 ]:
A Naming Quirk Worth Knowing

The C Parameter: Inverse Regularization Strength

scikit-learn's LogisticRegression doesn't use alpha like Ridge/Lasso did -- it uses C, and C works backwards from what you might expect.

Small C = strong regularization (heavily penalize large coefficients). Large C = weak regularization (barely penalize them at all). This is the opposite direction from alpha -- worth double-checking every time, since it's a very easy mix-up.

Like every other regularization strength in this course, C is a hyperparameter -- tune it with GridSearchCV, not by guessing.

In [ 15 ]:
Beyond Two Classes

Multiclass Logistic Regression: Softmax

Lecture 06 showed One-vs-Rest combining several binary classifiers. Logistic Regression has a second, more native option: softmax (multinomial) regression -- one equation that directly outputs a full probability distribution across all classes at once, guaranteed to sum to exactly 1.

LogisticRegression(multi_class='multinomial') (or the modern default, which picks this automatically when appropriate) fits one combined model instead of several separate one-vs-rest models -- often a more principled fit, since the classes are considered jointly rather than as separate binary problems stitched together.

In [ 16 ]:
When a Straight Line Isn't Enough

Assumptions and Limitations

Logistic Regression assumes the log-odds are a linear function of the features -- if the true boundary between classes genuinely curves, a plain logistic regression cannot represent it, no matter how it's trained.

The same fix as Lecture 02's polynomial regression: engineer curved or interaction features (Lecture 05) and feed them in -- the model is still "linear," now just linear in a richer, hand-expanded feature space. This is a real limitation, not a fatal one, as long as you remember to look for it (a residual-style check: does a more flexible model, like a tree, do noticeably better on the same data?).

The Honest Trade-offs

Strengths and Weaknesses

Strengths

  • Directly outputs calibrated probabilities, not just a ranking or a hard label
  • Coefficients are genuinely interpretable via odds ratios -- unlike a tree ensemble
  • Fast to train, even on large datasets
  • A strong, well-understood baseline almost always worth trying first

Weaknesses

  • Linear decision boundary only -- structurally cannot capture curved or interaction-heavy patterns without engineered features
  • Sensitive to feature scaling, like any gradient-descent-trained model
  • Assumes a fairly clean, mostly-linear relationship in log-odds space
